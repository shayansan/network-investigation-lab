# Phase 1 — Network Baseline, ARP, and ICMP Analysis

## Objective

The objective of this phase was to establish a controlled networking lab and analyze basic Layer 2 and Layer 3 communication from a Blue Team perspective.

The phase focused on:

- Network interface identification
- IPv4 addressing
- MAC addressing
- Neighbor discovery
- ARP resolution
- ICMP communication
- Packet capture using tcpdump
- Basic packet-flow reconstruction

---

## Initial Host Network Baseline

The initial investigation was performed on an Ubuntu system connected to a real network.

The active wireless interface was:

- Interface: `wlp2s0`
- IPv4 address: `10.2.20.128/18`
- MAC address: `24:ee:9a:1b:9f:68`
- Default gateway: `10.2.0.1`

Other interfaces included:

- `enp1s0f0` — Ethernet interface, down
- `docker0` — Docker bridge, `172.17.0.1/16`

The default gateway appeared in the neighbor table with a reachable MAC address.

Several listening services were also identified using `ss -tulpn`, including:

- SSH
- systemd-resolved
- CUPS
- Mosquitto MQTT
- mDNS-related traffic
- Chrony
- Python UDP traffic

---

## Problem Encountered on the Real Network

The real network produced significant background traffic.

After manually deleting the default gateway entry from the neighbor table, the entry was immediately recreated because background applications and operating system services continued generating network traffic.

This made it difficult to reliably capture the first ARP resolution generated by a controlled test.

A second issue was observed while running `tcpdump` inside Linux network namespaces. Packet output was buffered and did not immediately appear in the terminal.
